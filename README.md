# Кредитный кабинет предпринимателя

Учебный прототип на FastAPI с интерфейсом в стиле Альфа-Банка. Клиент подбирает
финансирование и подаёт заявку, сотрудник рассматривает её в отдельном кабинете.
Это не официальный сервис банка: проверки внешних источников используют моки,
кредитные договоры и выдача средств не выполняются.

## Быстрый запуск

Нужен Python 3.10 или новее. Выполняйте команды из корня проекта:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

В `.env` замените `SECRET` случайным секретом, например полученным командой
`python -c "import secrets; print(secrets.token_urlsafe(48))"`.
Для локального HTTP оставьте `COOKIE_SECURE=false`, для HTTPS задайте `true`.

```sh
uvicorn main:app --reload
```

Интерфейс: **http://127.0.0.1:8000/**. Документация REST API: **/docs**.
Таблицы SQLite создаются при запуске; база хранится в `app.db`.

## Возможности

### Кабинет клиента

1. Вход или регистрация — обязательный первый шаг оформления. Подтверждать email не нужно.
2. Свободное описание цели с подсказками, выбор суммы и срока.
3. Подбор вариантов через ИИ, включая варианты с более посильным платежом.
4. Ввод данных компании вручную или из документа. Индикатор доходов и плавный
   ползунок помогают скорректировать сумму.
5. Оценка рисков и согласование скорректированных условий. Крайне низкая оценка
   блокирует отправку и предлагает изменить условия.
6. Отправка заявки, просмотр статуса и истории, ответ на запрос уточнений сотрудника.

Заявки, документы, результаты проверок и история решений сохраняются на сервере.
В браузере остаются черновик и кеш заявок для текущего аккаунта. После изменения
данных нужна новая оценка; согласие с условиями каждый раз подтверждается отдельно.
Все оценки вероятности предварительные, окончательное решение принимает сотрудник.

### Кабинет сотрудника

Зарегистрируйте отдельный аккаунт и выдайте ему роль из консоли сервера:

```sh
python manage.py grant-staff --email employee@example.com
```

После обновления страницы в меню появится «Кабинет сотрудника». Сотрудник видит очередь
с фильтрами, данные компании, документы, результаты проверок, скоринг и историю.
Заявку нужно взять в работу, после чего можно повторить проверки, запросить
уточнение, одобрить или отклонить её с обязательным комментарием. Спорные случаи
помечены для ручного рассмотрения. Версия заявки защищает от одновременных решений.

Отозвать доступ: `python manage.py revoke-staff --email employee@example.com`.
Обычная регистрация и изменение профиля не дают роль сотрудника.

### Загрузка документов

Поддерживаются **PDF с текстовым слоем, DOCX, XLSX, CSV, TXT и JSON**, до 5 МБ на файл.
Сканы без текста и зашифрованные PDF не распознаются; PDF ограничен 20 страницами.
Перед переносом данных пользователь выбирает распознанные поля в окне проверки.
Документ может содержать название компании, ИНН, месячные выручку, расходы и платежи
по кредитам, возраст бизнеса в месяцах. Пример: [examples/company.json](examples/company.json).
Доступ к файлу имеют владелец и сотрудники при рассмотрении связанной заявки.

## Настройка CometAPI

Подбор и оценка рисков вызывают OpenAI-совместимый API на сервере:

```dotenv
COMETAPI_KEY=your-server-key
COMETAPI_MODEL=qwen3.8-flash
```

Модель по умолчанию — `qwen3.8-flash`, endpoint —
`https://api.cometapi.com/v1/chat/completions`. Старое имя переменной
`COMETAPI_API_KEY` также поддерживается; приоритет у `COMETAPI_KEY`.
Ключ храните только в `.env` или секретах сервера. После изменения настроек
перезапустите приложение.

Без ключа подбор возвращает ошибку настройки. При сбое API скрытой подмены
предложений нет. В тестах ответы модели подменены, платные запросы не выполняются.
Название компании, ИНН, email и файлы провайдеру не отправляются. Передаются цель,
уточнения, финансовые показатели и сводка проверок; учитывайте это при вводе текста.
Сервер проверяет предложенные условия и связывает их подписанным разрешением
с пользователем и данными заявки. Разрешение действует 30 минут.

При ошибке подбора проверьте строки `CometAPI failure` в `app.log`: они содержат
категорию ошибки, модель и HTTP-статус провайдера (если получен), без ключа и текста
заявки. Статусы 401/403 указывают на ключ или доступ, 402 — на баланс, 404 — на
недоступную модель, 429 — на лимит. Ответы не по схеме отмечаются `invalid_response`.
Если провайдер явно отклоняет параметр `response_format`, запрос один раз повторяется
без JSON-режима; проверка структуры и условий остаётся обязательной.

## Демонстрационные проверки и скоринг

Моки БКИ, ЕГРЮЛ/ЕГРИП и «Прозрачного бизнеса» детерминированы по ИНН:

| ИНН | Сценарий |
| --- | --- |
| `7701234560` | Нет флагов риска |
| `7701234578` | Просрочка 45 дней в БКИ, ручное рассмотрение |
| `7701234585` | Налоговая задолженность и массовый адрес, ручное рассмотрение |
| `7701234592` | Деятельность прекращена, блокировка отправки |

Для остальных валидных ИНН используется сценарий без флагов. Для ИНН из 12 цифр
показывается ЕГРИП, из 10 — ЕГРЮЛ. Результаты явно отмечены как моки.
Скоринг до 1000 баллов учитывает платёжную нагрузку, кредитную историю,
регистрационный статус, налоговые флаги и расхождения с документами.
Это демонстрационная формула, а не статистическая модель одобрения банка.

## Восстановление пароля

Для отправки ссылки настройте SMTP в `.env`:

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_FROM=no-reply@example.com
SMTP_USERNAME=your-smtp-user
SMTP_PASSWORD=your-smtp-password
SMTP_STARTTLS=true
RESET_PASSWORD_URL=http://127.0.0.1:8000/demo?flow=reset
```

При отсутствии авторизации SMTP имя и пароль можно оставить пустыми.
Поддерживается STARTTLS; неявный TLS на порту 465 не поддерживается.
Без SMTP письмо не отправляется. Для размещённого приложения укажите публичный
HTTPS-адрес формы в `RESET_PASSWORD_URL`.

## Проверки

Серверные тесты используют БД в памяти и подменённые внешние вызовы:

```sh
python -m unittest discover -s tests -v
```

Тесты интерфейса требуют Node.js 20.19 или новее:

```sh
npm install --prefix work/demo-js jsdom
NODE_PATH=./work/demo-js/node_modules node tests/test_demo_ui.cjs
```
