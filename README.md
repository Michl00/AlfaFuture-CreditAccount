# Кредитный кабинет предпринимателя

Пользовательский demo-интерфейс по мотивам кейса «Умный кредитный кабинет
предпринимателя». Визуальный стиль вдохновлён Альфа-Банком: красные акценты,
светлый кабинет, крупная типографика и карточки продуктов. Это учебный прототип,
не официальный сервис банка.

## Запуск

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

В `.env` задайте `SECRET` (случайный секрет JWT) и `COOKIE_SECURE=false`
для локального HTTP. Для HTTPS используйте `COOKIE_SECURE=true`.
Откройте **http://127.0.0.1:8000/** или **http://127.0.0.1:8000/demo**.

## Главная страница

Главная содержит только красный баннер с кнопкой «Подобрать финансирование»
и кнопку меню. Продукты, калькулятор, профиль и заявки открываются через меню.

## Пользовательский путь

1. **Регистрация.** Первый обязательный шаг — создание аккаунта или вход в
   существующий. После регистрации выполняется вход, затем открывается форма
   заявки. Гостевые заявки и черновики больше не создаются.
2. **Потребность.** Пользователь свободно описывает цель (от 3 до 500 символов),
   желаемую сумму и срок. Подсказки можно выбрать или отредактировать.
3. **Подбор.** Кабинет показывает несколько предварительных вариантов. Пользователь
   явно выбирает один из них, после чего переходит к данным компании.
4. **Компания.** Вводятся ИНН, название, выручка, расходы, действующие платежи и
   возраст бизнеса. Для демонстрации можно нажать «Заполнить примером».
   По мере ввода доходов, расходов и действующих платежей индикатор показывает
   качественную оценку вероятности одобрения: крайне низкая, низкая, средняя или высокая.
   При низкой оценке кнопка «Изменить» открывает отдельное окно с ползунком суммы.
   Сумма, платёж и оценка обновляются при движении ползунка; изменение сохраняется
   только после нажатия «Применить сумму».
5. **Предварительная оценка и согласование.** Модель оценивает нагрузку и
   предлагает корректировки суммы, срока и ставки. Таблица показывает выбранные
   и скорректированные условия, включая ежемесячный платёж и объяснения.
   При нехватке информации запрашивается уточнение. Если доступных условий нет,
   пользователь возвращается к параметрам. На этом этапе заявка ещё не отправлена.
6. **Подтверждение банка.** Только после отдельного согласия с итоговыми условиями
   пользователь отправляет демо-заявку. Она появляется в профиле и «Моих заявках»
   со статусом «Ожидает подтверждения банка». Автоматического одобрения банком нет.

Черновик сохраняет текущий этап и значения между посещениями. Галочка согласия
не восстанавливается: после возврата к условиям их нужно подтвердить заново.
Изменение данных требует новой оценки. Денежные поля разделяют разряды пробелами.

В интерфейсе нет REST-методов, JSON, HTTP-статусов и истории запросов.
Документация API доступна разработчикам отдельно по `/docs`.

## CometAPI и оценка рисков

Подбор вариантов и итоговая оценка рисков выполняются на сервере через
OpenAI-совместимый `POST https://api.cometapi.com/v1/chat/completions`.
Браузер не получает API-ключ. Установите зависимости из `requirements.txt`,
скопируйте `.env.example` в `.env` и задайте:

```dotenv
COMETAPI_API_KEY=your-server-key
COMETAPI_MODEL=exact-api-model-id-from-your-account
```

Для Qwen3.8-Flash нужен **точный API ID модели из кабинета CometAPI**.
Идентификатор публично не подтверждён, поэтому предположительное имя модели
не зашито в код. Значение `COMETAPI_MODEL` передаётся без подмены другой моделью.
После изменения переменных перезапустите приложение.

Без ключа или ID сервер возвращает понятную ошибку настройки. При таймауте,
ошибке провайдера или неправильном JSON нет скрытого перехода на локальные
предложения. Можно повторить запрос. Проверки разработки используют подменённые
ответы; реальные запросы и расходы в тестах отсутствуют.

### Пользовательский процесс

- Модель получает свободно введённую цель, сумму и срок, формирует 2–6 вариантов.
  Среди них есть более консервативные варианты с меньшей суммой/большим сроком
  и платежом. Сервер проверяет пределы суммы, срока, ставки и наличие хотя бы
  одного варианта с платежом не выше 85% исходного расчёта по соответствующему
  продукту. Только такой вариант получает значок «Высокий шанс одобрения».
  Это предварительная оценка структуры условий до анализа компании.
- После выбора та же настроенная модель получает контекст исходного запроса,
  выбранный вариант и финансовые показатели. Отдельные поля с названием компании,
  ИНН и электронной почтой не передаются провайдеру; свободные тексты цели и
  уточнения передаются как введены пользователем.
- Модель оценивает риски, объясняет изменения, корректирует сумму, срок и ставку.
  Сервер заново проверяет их пределы и посильность итогового платежа.
- Крайне низкая оценка модели (ниже 0,15), критический риск или явно непосильные
  условия блокируют отправку. Появляются сообщение и действие изменения условий.
  Если данных недостаточно, запрашивается уточнение.

### Плавный индикатор и ползунок

Мгновенный индикатор не вызывает ИИ на каждом движении ползунка. Он сравнивает
доступный платёж `0.5 × (выручка − расходы) − действующие кредитные платежи`
с аннуитетным платежом по текущим сумме, сроку и ставке.
Ширина шкалы рассчитывается непрерывно, вместо фиксированных скачков между
категориями; цвет меняется плавно, шаг суммы — 100 ₽. Проценты как статистический
прогноз не показываются. Когда доступный платёж ниже 30% требуемого, индикатор
становится крайне низким и блокирует переход к отправке. Уменьшение суммы может
снять блокировку, если показатели позволяют. Дополнительная проверка ИИ остаётся
обязательной. Все оценки предварительные, окончательное решение принимает банк.

### Серверная защита согласования

Все `/credit/*` методы доступны только авторизованному активному пользователю:

| Метод | Назначение |
| --- | --- |
| `POST /credit/recommendations` | Варианты и подписанный контекст исходного запроса |
| `POST /credit/assessments` | Проверка выбранного варианта, оценка модели, скорректированные условия |
| `POST /credit/confirm` | Проверка согласия и разрешения на точные условия перед созданием демо-заявки |

Разрешение на согласование подписано JWT, действует 30 минут и привязано к
пользователю, данным компании и конкретным итоговым условиям. Изменение данных,
подмена результата в браузере, чужой или просроченный токен не позволяют
завершить отправку. Перед подтверждением сервер повторно проверяет посильность.
Повторное подтверждение того же разрешения возвращает тот же идентификатор.
Пароли, ключи и тексты запросов к модели в журнал не записываются.

Банковская система пока не подключена. Подтверждение создаёт демонстрационную
заявку в профиле со статусом ожидания банка, без реального договора и выдачи
средств. Черновик и максимум 100 заявок по-прежнему хранятся в браузере отдельно
для каждого аккаунта, без синхронизации устройств. Подписанные доказательства
условий хранятся с черновиком; они не являются токенами входа и работают только
с активной сессией того же пользователя. Старые черновики без серверного
контекста требуют нового подбора.

## Проверки

API-тесты используют БД в памяти, письма подменены:

```sh
pip install httpx
python -m unittest discover -s tests -v
```

Правила кредитного сценария и DOM-интерфейс (Node.js 20.19+):

```sh
npm install --prefix work/demo-js jsdom
NODE_PATH=./work/demo-js/node_modules node tests/test_demo_ui.cjs
```

Для писем на demo-формы:

```dotenv
RESET_PASSWORD_URL=http://127.0.0.1:8000/demo?flow=reset
```

Форма подставляет токен из ссылки и убирает его из адресной строки.
Действие выполняется только после нажатия кнопки.

# Почтовые уведомления

Ссылки для сброса пароля отправляются через SMTP.
Укажите в `.env` (не добавляйте реальные пароли в Git):

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=your-smtp-user
SMTP_PASSWORD=your-smtp-password
SMTP_FROM=no-reply@example.com
SMTP_STARTTLS=true
RESET_PASSWORD_URL=https://app.example.com/reset-password
```

`SMTP_HOST`, `SMTP_FROM` и соответствующий URL необходимы для отправки письма.
Имя и пароль SMTP можно оставить пустыми, если сервер не требует авторизации.
По умолчанию используется порт 587 с STARTTLS и проверкой сертификата.
Для локального тестового SMTP без TLS задайте его порт и `SMTP_STARTTLS=false`.
Неявный TLS (порт 465) не поддерживается.

К URL добавляется параметр `token`; существующие параметры и фрагмент сохраняются.
Это адреса страниц интерфейса:
страница сброса отправляет `POST /auth/reset-password` с JSON `token` и `password`.
Можно использовать готовую форму `/demo?flow=reset`
или подключить свой интерфейс.
Адреса писем берутся из настроек, а не из заголовков запроса.
Токены и содержимое писем в журнал не записываются.
Ошибки конфигурации и SMTP передаются вызывающему коду; успешная отправка
не имитируется. При отключённом SMTP эти операции завершатся ошибкой.

Проверка почтового модуля: `python -m unittest discover -s tests -v`.
