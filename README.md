# Кредитный кабинет предпринимателя

Пользовательский demo-интерфейс по мотивам кейса «Умный кредитный кабинет
предпринимателя». Визуальный стиль вдохновлён Альфа-Банком: красные акценты,
светлый кабинет, крупная типографика и карточки продуктов. Это учебный прототип,
не официальный сервис банка.

## Запуск

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

В `.env` задайте `SECRET` (случайный секрет JWT) и `COOKIE_SECURE=false`
для локального HTTP. Для HTTPS используйте `COOKIE_SECURE=true`.
Откройте **http://127.0.0.1:8000/** или **http://127.0.0.1:8000/demo**.

## Что можно проверить

1. На главной выберите сумму и срок в калькуляторе либо один из трёх продуктов.
2. Нажмите «Оформить заявку». Укажите цель, сумму и срок.
3. На шаге «О бизнесе» нажмите «Заполнить примером» или введите вымышленные данные.
4. Проверьте условия, отметьте согласие и отправьте заявку.
5. Через несколько секунд в «Моих заявках» появится решение и следующий шаг.
6. При одобрении или предложении другой суммы примите демо-условия. Реальные
   договоры не заключаются, денежные операции не выполняются.
7. Закройте и снова откройте страницу: заявки и незавершённый черновик сохранятся
   в этом браузере. Черновик можно продолжить или удалить.

Техническая консоль удалена: клиент не выбирает REST-методы и не видит JSON,
HTTP-статусы, ответы сервера и историю запросов. Ошибки входа и заполнения форм
переводятся в понятные сообщения. API-документация для разработчика доступна
отдельно по `/docs`.

## Границы демонстрации

Существующий сервер отвечает за регистрацию, вход, выход, чтение и изменение
профиля, сброс пароля и подтверждение почты. Авторизация использует HttpOnly
cookie. Пароли и токены не сохраняются в хранилище браузера.

Кредитная часть — интерактивный клиентский прототип, а не реализованный
банковский конвейер. Черновик и максимум 100 заявок хранятся в `localStorage`:
отдельно для гостя и каждого ID аккаунта. Между устройствами данные не
синхронизируются. При недоступном хранилище работа продолжается в памяти вкладки
с предупреждением. Используйте только вымышленные данные.

Рассмотрение моделируется через 6 секунд и возобновляется после перезагрузки.
Ставки демонстрационные: 24,9%, 22,9% и 26,9% годовых. Платёж рассчитывается
по аннуитетной формуле. Правила в `static/demo/credit.js`:

- Бизнес младше 6 месяцев: запрос текстового уточнения, затем повторное рассмотрение.
- Доступный платёж: 50% разницы между месячной выручкой и расходами минус
  платежи по действующим кредитам.
- Если доступного платежа достаточно — одобрение выбранной суммы.
- Если хватает на меньшую сумму от 100 000 ₽ — альтернативное предложение,
  округлённое вниз до 10 000 ₽.
- В остальных случаях — отказ с объяснением и возможностью подать новую заявку.

Это исключительно демонстрационная логика, не скоринг и не условия Альфа-Банка.
Проверки реестров, кредитных историй, документов, подписание и выдача средств
не подключены. Требования PDF использованы как продуктовый ориентир;
полный комплект конкурсного решения не входит в эту доработку интерфейса.

Примеры сценариев для суммы 1 500 000 ₽ и срока 24 месяца:

| Сценарий | Выручка / мес. | Расходы / мес. | Кредиты / мес. | Возраст бизнеса |
| --- | --- | --- | --- | --- |
| Одобрение | 1 200 000 ₽ | 700 000 ₽ | 20 000 ₽ | 24 мес. |
| Меньшая сумма | 1 200 000 ₽ | 1 000 000 ₽ | 50 000 ₽ | 24 мес. |
| Отказ | 1 200 000 ₽ | 1 200 000 ₽ | 20 000 ₽ | 24 мес. |
| Уточнение | 1 200 000 ₽ | 700 000 ₽ | 20 000 ₽ | 2 мес. |

Для тестового ИНН можно использовать `7701234560` с корректной контрольной суммой.
Название компании в примере вымышленное, поиск в реестрах не выполняется.

## Проверки

API-тесты используют БД в памяти, письма подменены:

```sh
pip install httpx
python -m unittest discover -s tests -v
```

Правила кредитного сценария и DOM-интерфейс (Node.js 20.19+):

```sh
npm install --prefix work/demo-js jsdom
NODE_PATH=./work/demo-js/node_modules node tests/test_demo_ui.cjs
```

Для писем на demo-формы:

```dotenv
RESET_PASSWORD_URL=http://127.0.0.1:8000/demo?flow=reset
VERIFICATION_URL=http://127.0.0.1:8000/demo?flow=verify
```

Форма подставляет токен из ссылки и убирает его из адресной строки.
Действие выполняется только после нажатия кнопки.

# Почтовые уведомления

Ссылки для сброса пароля и подтверждения почты отправляются через SMTP.
Укажите в `.env` (не добавляйте реальные пароли в Git):

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=your-smtp-user
SMTP_PASSWORD=your-smtp-password
SMTP_FROM=no-reply@example.com
SMTP_STARTTLS=true
RESET_PASSWORD_URL=https://app.example.com/reset-password
VERIFICATION_URL=https://app.example.com/verify-email
```

`SMTP_HOST`, `SMTP_FROM` и соответствующий URL необходимы для отправки письма.
Имя и пароль SMTP можно оставить пустыми, если сервер не требует авторизации.
По умолчанию используется порт 587 с STARTTLS и проверкой сертификата.
Для локального тестового SMTP без TLS задайте его порт и `SMTP_STARTTLS=false`.
Неявный TLS (порт 465) не поддерживается.

К URL добавляется параметр `token`; существующие параметры и фрагмент сохраняются.
Это адреса страниц интерфейса:
страница сброса отправляет `POST /auth/reset-password` с JSON `token` и `password`,
а страница подтверждения — `POST /auth/verify` с JSON `token`.
Можно использовать готовые формы `/demo?flow=reset` и `/demo?flow=verify`
или подключить свой интерфейс.
Адреса писем берутся из настроек, а не из заголовков запроса.
Токены и содержимое писем в журнал не записываются.
Ошибки конфигурации и SMTP передаются вызывающему коду; успешная отправка
не имитируется. При отключённом SMTP эти операции завершатся ошибкой.

Проверка почтового модуля: `python -m unittest discover -s tests -v`.
