# API кредитного кабинета

Базовый путь — `/api/v1`, JSON в UTF-8. В Compose origin `http://localhost:8080`, локально `http://127.0.0.1:8000`. Интерфейс и API используют один origin.

[OpenAPI](openapi.json) генерируется из FastAPI и содержит также исторические маршруты `/auth`, `/users`, `/api/credit` и другие. Новый кабинет использует только `/api/v1`; его демосессия не взаимозаменяема с исторической авторизацией. Точные пути, поля, типы и ограничения входных моделей смотрите в схеме. Многие ответы реализованы как словари без `response_model`, поэтому автоматически выгруженная схема не описывает все поля ответов и бизнес-ошибки; они пояснены ниже.

## Сессия и доступ

1. При `DEMO_MODE=true` отправить `POST /demo/login` с `{"profile":"ooo"}` (`ip` — ИП, `bank` — сотрудник).
2. Сохранить cookie `conveyor_session` и `csrf` из JSON-ответа. Cookie имеет HttpOnly, SameSite=Lax, срок 4 часа; Secure зависит от `COOKIE_SECURE`.
3. Передавать cookie во всех закрытых запросах, а `X-CSRF-Token: <csrf>` — также в изменяющих запросах. `GET /me` возвращает профиль, CSRF и сводку.
4. `POST /logout` отзывает текущую сессию. Новый вход в том же cookie-контексте заменяет её; CSRF нужно обновить.

В браузере вход проверяет `Origin` относительно `PUBLIC_ORIGIN` или origin запроса. CLI-клиент может не посылать `Origin`. Публичны `/demo`, `/demo/login`, `/catalog`, `/health`. Остальные маршруты требуют сессии. Клиент видит свои заявки; сотрудник видит общую очередь. Чужая заявка для клиента возвращает 404.

Cookie и CSRF проверяются зависимостью FastAPI и не объявлены отдельной security-схемой OpenAPI для `/api/v1`. Для ручной проверки используйте [коллекцию](requests.http), которая сохраняет cookie, либо войдите через кабинет на том же origin перед работой в Swagger.

## Маршруты

Все пути в таблице относительно `/api/v1`. Успешный ответ — 200, если не указано иное.

| Метод и путь | Доступ | Назначение |
| --- | --- | --- |
| `GET /demo` | Публичный | Доступность деморежима и профили |
| `POST /demo/login` | Публичный, деморежим | Вход, cookie и CSRF |
| `GET /me`, `POST /logout` | Сессия | Профиль/сводка и выход |
| `GET /catalog` | Публичный | Продукты, лимиты, тестовые сценарии |
| `GET /draft`, `PUT /draft` | Клиент | Один серверный черновик на компанию; GET может вернуть `null` |
| `POST /assessments` | Клиент | Расчёт, `assessment_id`, `fingerprint`, `review_state=pending` |
| `POST /assessments/{id}/review` | Владелец | Постановка заключения в очередь: 202; готовое заключение: 200 |
| `GET /assessments/{id}` | Владелец | Статус и `ai_review`; `include_result=true` добавляет данные и расчёт |
| `POST /applications` | Клиент | Согласие и отправка; 201, в том числе при идемпотентном повторе |
| `GET /applications` | Сессия | Список/очередь: `status`, `q`, `limit`, `offset` |
| `GET /applications/{id}` | Владелец/сотрудник | Карточка, расчёт и история |
| `GET /applications/{id}/state` | Владелец/сотрудник | Короткий ответ: `id`, `status`, `version` |
| `GET /applications/{id}/revisions` | Владелец/сотрудник | Снимки версий по возрастанию |
| `POST /applications/{id}/actions` | Сотрудник | `approve`, `reject`, `request_info`, `recheck`, `offer`, `sign`, `pay`, `settle` |
| `POST /applications/{id}/reply` | Клиент-владелец | Ответ на уточнение или явное принятие/отклонение оффера |
| `POST /applications/{id}/explanation` | Владелец/сотрудник | Сохранённое заключение либо объяснение из фактов |
| `GET /documents/demo` | Клиент | Перечень типов синтетических документов |
| `POST /documents/preview` | Клиент | Синтетический пакет по полям анкеты `Input` |
| `GET /documents` | Клиент | Документы из сохранённых расчётов своих заявок |
| `GET /chat`, `POST /chat` | Сессия | История и ответ помощника; необязательный `application_id` |
| `POST /chat/{id}/draft` | Клиент-владелец | Перенос предложения помощника в черновик |
| `GET /feed` | Сессия | До 20 последних разрешённых событий из последних 200 заявок |
| `GET /health` | Публичный | Проверка БД, `status` и деморежим |

`GET /applications` возвращает `items`, `total`, `offset`, `has_more`, `summary`. Поиск по ID, цели и ИНН выполняется до пагинации. `limit` ограничивается диапазоном 1–100, `offset` снизу нулём; сводка относится ко всему доступному портфелю. Карточки списка содержат сокращённый `assessment` и пустой `events`.

## От расчёта до заявки

Анкета `Input` содержит продукт, сумму, срок, цель, ИНН компании, месячные выручку/расходы/налоги/внешние платежи, остаток денег, возраст бизнеса, признаки документов и тестовые факторы. Суммы вводятся в рублях, срок и возраст — в месяцах. ИНН должен совпадать с профилем. Дополнительные неизвестные поля и нечисловые бесконечности запрещены; лимиты проверяются по выбранному продукту.

```json
{
  "product": "working", "amount": 1500000, "months": 24,
  "goal": "Пополнение оборотных средств", "inn": "7701234560",
  "revenue": 1500000, "expenses": 900000, "taxes": 50000,
  "debt": 20000, "cash": 500000, "age": 36,
  "scenario": "clean", "documents_attached": true
}
```

`POST /assessments` сохраняет нормализованную анкету и результат с `terms`, `plan`, `base`, `stress`, `checks`, `rules`, `alternatives`, `policy_version`, `catalog_version`. До отправки требуется запросить `/review` и опрашивать GET до `done` или `unavailable`. Последний означает готовое резервное объяснение по правилам и также разрешает продолжить процесс. Запущенный worker обязателен даже без ключа модели.

```json
{
  "assessment_id": "<assessment_id>",
  "data": {
    "product": "working", "amount": 1500000, "months": 24,
    "goal": "Пополнение оборотных средств", "inn": "7701234560",
    "revenue": 1500000, "expenses": 900000, "taxes": 50000,
    "debt": 20000, "cash": 500000, "age": 36,
    "scenario": "clean", "documents_attached": true
  },
  "fingerprint": "<fingerprint из расчёта>",
  "consent": true
}
```

Замените `assessment_id` и `fingerprint` значениями своего расчёта. Заголовок `Idempotency-Key` обязателен: 8–80 символов. Ключ привязан к компании и хешу тела; повтор того же запроса возвращает ту же заявку, другое тело с тем же ключом — 409. Срок автоматической очистки ключей не реализован.

Расчёт действует 30 минут. Перед сохранением сервер заново учитывает портфель. Изменение анкеты, условий или обязательств требует нового расчёта и согласия. Отказная заявка тоже сохраняется для просмотра результата и истории.

## Команды и ответы

Команда сотрудника содержит актуальную `version`, `action`, `comment` (10–2000 символов, после удаления пробелов минимум 10). Для `offer` нужны `amount` и `months`; `sign` и `pay` поддерживают `simulate_failure`. Любая сохранённая команда увеличивает версию, включая неуспешную симуляцию. Новую версию берите из ответа.

Ответ на уточнение содержит `version`, `comment`, исправленную анкету `data` и новый завершённый `assessment_id`. Ответ на оффер содержит `version`, `comment`, `accept_offer: true|false`. Оффер действует 30 минут; принятие повторно проверяет неизменность расчёта. [Все переходы и ограничения](application-states.md).

## Ошибки

Бизнес-ошибка обычно имеет вид `{"detail":"APPLICATION_CHANGED"}`; ошибка валидации Pydantic — `{"detail":[{"loc":[...],"msg":"...","type":"..."}]}`. Каждый HTTP-ответ получает `X-Request-ID`; при необработанной ошибке 500 тело также содержит `request_id` и `detail: INTERNAL_ERROR`. Единого объекта `code/message/field_errors` пока нет.

| HTTP | Примеры `detail` | Действие клиента |
| --- | --- | --- |
| 401 | `SESSION_REQUIRED` | Повторить вход |
| 403 | `CSRF_REQUIRED`, `CLIENT_REQUIRED`, `STAFF_REQUIRED`, `ORIGIN_REJECTED` | Проверить CSRF, профиль и origin |
| 404 | `APPLICATION_NOT_FOUND`, `ASSESSMENT_NOT_FOUND`, `DEMO_DISABLED` | Проверить ID, владельца и деморежим |
| 409 | `ASSESSMENT_EXPIRED`, `ASSESSMENT_CHANGED`, `AI_REVIEW_REQUIRED` | Дождаться заключения или пересчитать и подтвердить |
| 409 | `IDEMPOTENCY_CONFLICT`, `APPLICATION_CHANGED` | Использовать ключ для нового запроса; перечитать карточку перед командой |
| 409 | `FINAL_APPLICATION`, `REPLY_NOT_ALLOWED`, `CONTRACT_REQUIRED`, `OFFER_EXPIRED`, `OFFER_CHANGED` | Проверить состояние, оформление и условия |
| 422 | `POLICY_BLOCKED`, `OFFER_POLICY_BLOCKED`, `GUARANTEE_HAS_NO_DISBURSEMENT`, ошибки полей | Исправить данные; обязательные запреты нельзя обойти командой |
| 429 | `REVIEW_RETRY_LATER` | Повторить запрос заключения позже (не ранее 30 секунд от последнего старта) |

## Обновление контракта

Из корня репозитория, после установки Python-зависимостей:

```sh
.venv/bin/python scripts/export-openapi.py
.venv/bin/python scripts/export-openapi.py --check
```

Экспорт вызывает `app.openapi()` без запуска lifespan, подключения к БД и обращения к провайдеру. После изменения маршрутов обновите также описание API и коллекцию.
