# Документация для проверки

Комплект описывает реализованный Astro-кабинет и API `/api/v1`. Запуск и демонстрационный вход — в [корневом README](../README.md#быстрый-запуск). Все компании, проверки, документы и операции с деньгами синтетические.

| Материал | Содержание |
| --- | --- |
| [Архитектурная схема](architecture.md) | Компоненты, интеграции, worker, согласованность и ограничения |
| [Описание API](api.md) | Доступ, маршруты, последовательность вызовов и ошибки |
| [OpenAPI](openapi.json) | Выгрузка реальных маршрутов и входных схем FastAPI |
| [Коллекция HTTP-запросов](requests.http) | Вход → расчёт → заключение → отправка → оформление → выдача → погашение |
| [Диаграмма состояний заявки](application-states.md) | Все статусы, команды, условия переходов и состояния заключения |
| [Модель данных](data-model.md) | ER-диаграмма, таблицы, JSON-снимки и ограничения |
| [Тестовые сценарии](testing.md) | Предусловия, шаги, ожидаемые результаты и связь с автотестами |
| [Сверка с кейсом](case-verification.md) | Соответствие требованиям и границы MVP |
| [План развития](implementation-plan.md) | Проектные предложения; не перечень готовых функций |

На запущенном Compose-стенде доступны [Swagger UI](http://localhost:8080/docs) и [актуальная схема](http://localhost:8080/openapi.json). При запуске без Docker замените адрес на `http://127.0.0.1:8000`.

Начните с основного сценария в `testing.md` или выполните `requests.http` по порядку. Для повторной проверки используйте отдельную чистую БД: одобренные обязательства влияют на следующие расчёты. Идентификатор сдаваемой версии определяется командой `git rev-parse HEAD`; фиксация release-тега выполняется отдельно перед сдачей.
