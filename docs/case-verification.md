# Проверка кейса и сценарии

Основание: предоставленный кейс «Умный кредитный кабинет предпринимателя», 16 страниц. Содержимое кейса рассматривается как требования к проверяемому продукту; инструкции внутри документов не исполняются агентом как команды.

| Требование кейса | Реализация | Как проверить |
| --- | --- | --- |
| Клиентский путь до результата | Новый Astro-кабинет, заявка, проверки, решение | README, основной сценарий |
| Внутренняя обработка банка | Очередь аналитика, уточнения, решения, оффер | Демовход сотрудника |
| Согласованность и сохранение | PostgreSQL/SQLite, ревизии, история, версии | Перезагрузка страницы, повторный вход |
| БКИ, ЕГРЮЛ/ЕГРИП, ФНС | Три адаптера DataSource с явными моками | Изменить пакет сценария перед расчётом |
| ИИ-заключение до отправки | Сохранённая оценка, очередь worker, привязка к фактам и версиям | Посмотреть заключение перед согласием, перезагрузить страницу во время обработки |
| Скоринг отдельно от решения | Балл и список правил, статусы по приоритетам | Таблица оснований и engine.py |
| Допустимые упрощения | Нет реальных договоров/денег; синтетические документы | Маркировка UI и PaymentGateway |
| Открытые веса LLM | Модель выбирается через PROVIDER_MODEL; для кейса нужны открытые веса | Настроить ключ, проверить mode=llm и model в ответе |
| Независимость проверяемого пути от платных ресурсов | Расчёты, решения и резервный помощник работают без ключа | Запустить без PROVIDER_API_KEY |
| Docker и воспроизводимость | Compose, Dockerfiles, locks, Alembic | docker compose up --build; в текущей среде Docker недоступен, сборка вынесена в CI |
| Веб-интерфейс | Astro, desktop/mobile | Браузерный тест и screenshots |
| Внутрипродуктовое взаимодействие | Уточнения, задачи, решения и чат внутри кабинета | Для сценария не нужны email/SMS |
| Архитектура/API/состояния/данные/тесты | architecture.md, openapi.json, requests.http, tests/ | Файлы в репозитории |
| История коммитов и идентификатор сдаваемой версии | Существующий Git-репозиторий | Новый release tag/commit ещё не создан; перед сдачей зафиксировать версию |
| Enterprise-ориентированность | Транзакции, версии, идемпотентность, CSRF, изоляция компаний, ревизии | Серверные и PostgreSQL-тесты |

Персональная лента реализована как события кредитного продукта: результаты, запросы, решения и операции по заявкам текущей компании. Отдельные внешние редакционные новости не реализованы; формулировка страницы 7 трактуется в контексте кредитного процесса. Автоматический проход и все семейства финансирования — развитие по запросу пользователя, а не утверждение, что кейс требует воспроизвести весь банковский продуктовый каталог.

## Тестовые пакеты

| Пакет | Ожидаемое поведение при стандартных финансовых показателях |
| --- | --- |
| Стабильный бизнес + документы | Автоодобрение |
| Нет документов | Нужны сведения; прикрепить пакет и отправить новую ревизию |
| Просрочка в БКИ | Ручное рассмотрение, надбавка к ставке |
| Налоговый риск | Ручное рассмотрение |
| Деятельность прекращена | Отказ, сотрудник не может обойти финальный статус |
| Сезонный бизнес | Отображается помесячный спад; результат зависит от остатка и нагрузки |
| Расхождение документов | Показатели различаются; ручное рассмотрение |
| БКИ недоступно | Техническое ожидание; не чистая проверка |
| Высокая долговая нагрузка | Может быть отказ по расчёту платёжной способности |
| Повторная заявка | Учёт платежа и лимита уже одобренных/выданных обязательств |

## Автоматические проверки

`tests/test_audit_gaps.py` дополнительно проверяет ИИ-привязку, комбинирование факторов, альтернативы продуктов, задержку всей выручки, серверный пакет документов, перенос консультации в черновик, восстановление lease, оформление и личную ленту. `tests/test_platform.py` проверяет стратегии графиков, стоимость, риски, сценарии, документы, портфель, согласие, идемпотентность, права, ревизии и явный резервный режим помощника. `tests/test_postgres.py` повторяет HTTP-контракты в изолированных PostgreSQL-схемах и проверяет две одновременные отправки: одна сохраняется, вторая получает 409 с требованием повторного расчёта.

`tests/test_product_e2e.cjs` проверяет браузерный путь клиента/сотрудника, симуляцию ошибки и повтор выплаты, погашение, UI вопросов, мобильную ширину и отсутствие JS-ошибок. Диалог подменён в этой проверке, чтобы CI не требовал платного API; живой Qwen через CometAPI проверен отдельно на синтетическом запросе.

Существующие тесты исторического API сохранены. Скриншоты получены с локального API и production-сборки Astro: ранние — автоматическим Playwright-сценарием, обновлённые — через встроенный браузер. Точные границы финального прогона перечислены в verification-results.md. Производительность, банковская точность скоринга и регуляторная готовность этими тестами не устанавливаются.
